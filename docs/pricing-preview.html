Product

Secure defaults. Explicit boundaries.

Start with a small client API, then compose the infrastructure your application actually needs.

01 · CLIENT

Message-first application API

Create one client per device, sync public prekeys, send encrypted messages, and receive decrypted content through application-owned hooks.

02 · IDENTITY

Trust that fails closed

Versioned X25519 and Ed25519 composite identities, explicit unverified first contact, authenticated safety numbers, and controlled rotation.

03 · COMPOSITION

Infrastructure without lock-in

Keep device secrets local. Connect a relay for delivery and public keys. Add encrypted object storage for durable attachments.

Architecture

The server connects devices. It does not become the trust anchor.

Each device owns its protocol state and plaintext. Remote services carry public material, routing metadata, encrypted envelopes, and encrypted object bytes.

  • Your devicePrivate keys, sessions, plaintext, local files, and trust decisions.
  • RelayDevice discovery, public prekeys, fanout, delivery, and acknowledgements.
  • Object storeOpaque encrypted attachment bytes and retry-safe pointers.

Developer experience

Small surface. Serious protocol machinery.

Use the root package for portable APIs and explicit subpaths for platform and backend adapters. Secure post-quantum policy is the default path.

browsernodeexpotypescript
quick-start.ts
// Real protocol and cryptography; simulated in-memory infrastructure.
import { createSignalProtocolClient } from '@open-e2ee/signal-protocol-sdk';
import { mockStore } from '@open-e2ee/signal-protocol-sdk/local/store/mock';
import { mockRelay } from '@open-e2ee/signal-protocol-sdk/remote/relay/mock';

const relay = mockRelay();
await relay.registerDevice('alice', { encryptedDeviceName: new ArrayBuffer(0) });
await relay.registerDevice('bob', { encryptedDeviceName: new ArrayBuffer(0) });

const alice = await createSignalProtocolClient({
  identity: { userId: 'alice' },
  adapters: { storage: mockStore(), relay },
});
const bob = await createSignalProtocolClient({
  identity: { userId: 'bob' },
  adapters: { storage: mockStore(), relay },
});

await alice.syncToServer();
await bob.syncToServer();

const delivered = new Promise<void>((resolve) => {
  bob.registerHook('onMessageDecrypted', async (message) => {
    console.log(`${message.senderId}: ${message.content}`);
    resolve();
  });
});

await alice.send('bob', 'hello');
bob.startRelaySubscription();
await delivered;

FAQ

Clear commercial boundaries.

The exact agreement would control. This preview records the proposed model from the planning discussion.

Does Cloud include the commercial SDK license?

Yes. The proposed Managed Cloud plans bundle commercial production rights for the applications included in the plan.

What counts as one application?

A separately shipped product. The same product across development, staging, web, iOS, Android, Expo, and Node counts as one application.

Do additional devices increase Relay MAU?

No. Relay MAU counts one unique tenant end-user active in a month. Additional devices affect delivery usage, not MAU.

What happens when a license expires?

Annual self-hosted customers keep perpetual rights to the last SDK version received for the named product. Updates and support end. Monthly Cloud customers receive a proposed 90-day migration window.

Is this wire-compatible with Signal Messenger?

No general compatibility claim is made. This is an independently versioned TypeScript profile based on selected Signal Protocol specifications.
